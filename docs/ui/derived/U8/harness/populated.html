Skills on disk, not mapped to agents

24 skills in .claude/skills, counted from the fixture, in file order. The fixture lists them but does not link any to an agent.

architecture
The architecture contract for Uinsure.Policies: projects, references, key types, where rules live, HTTP edge, persistence, cross-cutting rules, architecture tests, banned APIs and approved packages.
code-quality
Code quality at this project's size: SOLID without ceremony, DI only at real seams, the rule of three, and the slop list. Applied by the builder when writing and by the reviewer when judging.
creative-direction
The method the creative-director runs to turn research into three divergent, cited design territories for Docket's two halves: concept first, layout derived, excludes that stop re-convergence, one signature move per half, a derived palette that passes contrast.
directions
Design stage 2 for the ui plan: dispatch the creative-director once with a script-rendered prompt to write three cited, divergent territories to docs/ui/directions.json, validate them in the parent, and open the PR into ui. No gate: David judges the territories as mockups at G2.
dotnet10-webapi
Only the .NET 10 Web API techniques this project uses: controllers and DataAnnotations, strict JSON, the unknown-query filter, ProblemDetails mapping, TimeProvider, the EF Core provider switch, health, logging.
feature
Run the feature loop for one plan node: walk its DAG tasks, dispatch the six agents, run every gate yourself with receipts, apply the retry ladder, and stop at David's two pauses. Main session only.
git-workflow
The git agent's operations: branch and worktree naming, exact commands per op, rebase plus full suite, PR body and comment templates, the dpmorgandev-only comment filter, reply format and refusals.
interface-craft
The generative method the ui-designer runs to author an application screen that is alive rather than a spreadsheet: the question, the place, the data's shape, type, one signature, every state, one action.
load-context-chain
Read the docs/context/ snapshot chain on the current branch and synthesise where the work stands, then stop and ask David to confirm before resuming. Read-only. Use at session start (via /orient) and after a compact reload.
mockups
Design stage G2 for the ui plan: dispatch ui-designer once per territory × screen with a script-rendered prompt, lint each artifact, render the screenshot review, and stop for David to pick a direction.
orient
Gather as much project context as possible before work begins, covering requirements, spec status, plans, git, PRs and the trail in flight, then run /load-context-chain and wait for David. Project-only and read-only. Use at the start of every session.
owasp-api-security
The security checklist for this API: OWASP API Security Top 10 2023 mapped In/Out, a grep per check, the .NET extras, and the P0/P1/P2 severity rubric.
plan-bug
Draft a bug plan (docs/plans/active/bug-NNN.plan.md + bug-NNN.dag.yaml) for a defect found after merge - symptom, the broken rule, the introducing commit, a micro-DAG whose N1 t1 is the failing reproduction test. Main session only. Writes drafts in the main checkout; David approves; /feature runs it.
plan-dag
Draft the build plan from the planning Contract and requirements.md, after asking David once - docs/plans/active/build.dag.yaml (the DAG with explicit tasks the orchestrator loops through) and build.plan.md (the reasoning). Main session only, run once in F0a. Writes drafts; David approves by his own commit on main.
plan-investigation
Read-only investigation of one falsifiable question - docs/plans/active/inv-NNN.plan.md with question, hypothesis, evidence, findings and recommendations (feature | bug | amend-node) for David to accept or reject. Never changes code, never writes a DAG. Main session only; it is /feature's attempt-3 escalation, or David's own question.
react-kit
How the kit-builder writes Docket's React kit: one folder per component with its CSS Module, examples and index; tokens only; props in, markup out; behaviour tests per state; BUSY-1; accessibility; the kitchen sink.
requirements-trace
Rule ID ↔ test traceability: the trait convention, success and failure rows per rule, red-before-green per rule from the trailer log, no weakened assertion, no stub left, status codes per the contract.
root-cause
Root-cause diagnosis of a FAIL or a David steer: work from the evidence, one cause per finding with file:line, symptom vs cause, fix direction without code, testable or not, and the findings JSON.
save-context
Write a session snapshot to docs/context/ so work can resume across sessions and days. Main session only. Use at node boundaries (step change, verdict, attempt increment, HITL hand-off), after a confirmed compact reload, or when David asks.
screen-contract
How the ui-designer writes a screen at G4: static HTML pages built from the stylekit's pasted markup, one page per state, every region tagged, with a screen.json manifest. The screen is the contract the UI build nodes are held to, not the app.
screens
Design stage G4 for the ui plan: derive the design fixture, fix the kit's carried defects, generate the stylekit, then dispatch ui-designer for every screen as a static HTML contract, six in parallel with script-rendered prompts, audit each wave in the parent, and stop for David's sign-off.
stylesheet
Design stage G3 for the ui plan: scaffold the web project, derive the tokens from the chosen territory, dispatch kit-builder batch by batch in dependency waves with script-rendered prompts, check every wave in the parent, audit the kitchen sink against the catalog, and stop for David's sign-off.
tdd-outside-in
Outside-in TDD for one plan node: the step order, what red means, the throwing-stub rule, test conventions, the integration harness, Postman naming and the QA script template.
verdict-format
The verdict JSON schema v1 for reviewer and security, with its PASS/FAIL semantics. Your final message is exactly one object that validates against it.
