Researched 2026-10-19 by a read-only local subagent (Sonnet) over the main checkout at `ad7b6b0` plus the

the build moves. The compiler (DATA-8) reads whatever exists at build time.

## 1. Entities

Provenance labels (generated, recorded, written) come from each file's first line and
`docs/trace/README.md`.

**D1 Rule** (generated: `docs/trace/requirements-matrix.md`; written: `docs/requirements.md` §2)
- `requirements.md` tables: `ID`, `Rule`, `Agreed interpretation`, under "Sell (MUST-1)", "Retrieve
  (MUST-2)", "Cancel (SHOULD-1)", "Renew (SHOULD-2)", "Could-haves".
- Matrix columns: `rule`, `plan/node`, `tests (pass/total)`, `red`, `green`, `refactor`, `QA step`,
  `sign-off`, `PR`. The matrix has no rule-text column.
- Built: `SELL-1 | build/F1 | 22/22 | b716734 | 7d3f791 | | docs/qa/build-F1.md#1 | David 2026-10-18 | #10`.
- Not built: `CANCEL-1a | build/F3 | not built yet |` and empty cells.
- Any of `red`, `green` and `refactor` may be empty on a built row (a rule can be built with no refactor
  commit, or pinned with no green of its own). Example refactor SHA: `GET-1` `80d3ee2`.

**D2 Plan** (written: `docs/plans/active/build.dag.yaml`, `build.plan.md`, `inv-001.plan.md`)
- DAG: `plan_id`, `kind`, `title`, `status` (`approved`), `created`, `approved_by`, `approved_on`,
  `requirements_rev` (`d56e048`), `parent`.
- `build.plan.md`: Why, Approach, Rejected alternatives, Prior work consulted, Attempt log, Completion
  record.
- `inv-001.plan.md` frontmatter: `plan_id: inv-001`, `kind: investigation`, `title`, `created`,
  `dag: null`, `parent: build/F2`; headings Question, Hypothesis, Evidence, Findings, recommendations.

**D3 Node** (DAG `nodes[]`): `id`, `title`, `kind`, `owner`, `depends_on[]`, `rules[]`, `cuttable`,
`budget`, `status`, `attempt`, `branch`, `worktree`, `pr`, `qa`, `trace`, `acceptance[]`, `tasks[]`.
Example: `id: F2`, `title: Retrieve`, `kind: feature`, `owner: loop`, `depends_on: [F1b]`,
`rules: [GET-1]`, `attempt: 3`, `branch: feature/build/F2`, `pr: 17`.

**D4 Task** (`tasks[]`): `id`, `role`, `step`, `layer`, `rules[]`, `title`, `status`. Example:
`{id: t5, role: builder, step: green, layer: domain, rules: [GET-1], title: "Policy derives status and
the current term from DateOnly today", status: skipped}`.

**D5 Attempt** (no file of its own): derived from `attempt` on every loop event, `attempt++` events, and
verdict and finding filenames. The README "Loop" line summarises, e.g. `attempt 2: security PASS ·
attempt 2: reviewer FAIL · attempt 3: security PASS`.

**D6 Gate / loop event** (generated: `docs/trace/build/<node>/loop.jsonl`; subset in
`packet/gates.jsonl`)
- Always: `v` (int), `ts` (ISO), `plan`, `node`, `attempt` (int), `source`, `event`, `head` (SHA).
- Optional: `cmd`, `exit` (int), `expect`, `ok` (bool), `detail`, `head_sha`, `passed`, `failed`.
- Example: `{"event":"gate.stub","exit":2,"expect":"every GET-1 test fails","ok":false,"head":"305789df…"}`;
  detail `25 total, 13 failed, 12 passed. (a) 5 pass by the canned status Active coinciding: …`.

**D7 Activity event** (generated by hook: `activity.jsonl`): `v`, `ts`, `plan`, `node`, `attempt`,
`agent`, `agent_id` (nullable), `tool`, `tool_use_id`, `file` (nullable), `command` (nullable); optional
`commit` `{sha, subject, tdd}` (`tdd` may be null). Examples: `"agent":"main","tool":"Write",
"file":"<outside-repo>","command":null`; `"commit":{"sha":"d0063dc6…","subject":"plan(build/F2): pending
→ in_progress","tdd":null}`.

**D8 Commit** (generated: `walkthrough.md`, `packet/trailers.txt`, README "Who touched what")
- Walkthrough: `#`, `sha`, `TDD`, `layer`, `rule`, `agent`, `what it did`. Example:
  `5 | 94a7473 | red | tests | GET-1 | tester | retrieve answers the full policy response, …`.
- Who touched what: `commit`, `Agent trailer`, `files` (count), `hook-log agent`, `match` (✓/✗).
- `trailers.txt`: `<40-char sha> <subject>`, then `Agent:`, `Plan:`, `Node:`, `Rule:`, `TDD:`,
  `Fixes-Finding: A1/I1`, `Co-Authored-By:`, blank-line separated.

**D9 Verdict** (recorded: `verdicts/<round>-<reviewer|security>.json`)
- Envelope: `v`, `ts`, `plan`, `node`, `attempt`, `agent`, `agent_id`, `verdict{}`.
- Inside: `schema_version`, `agent`, `plan_id`, `node_id`, `attempt`, `base_sha`, `head_sha`,
  `diff_fingerprint`, `verdict`, `gate_refs[]`, `rules_covered[]`, `rules_missing[]`, `findings[]`,
  `notes[]`.
- Finding: `id`, `rule_id`, `severity`, `file`, `line`, `what`, `why`, `route_to`. Example:
  `"verdict":"FAIL"`, `"rules_missing":["GET-1"]`, `"id":"R1","severity":"P1",
  "file":"src/Uinsure.Policies.Api/Contracts/PolicyMappings.cs","line":37,"route_to":"tester"`.
- Security: `"rules_covered":["API3:2023", …, "NET:money"]`, `"findings":[]`, notes like
  `n/a API1:2023: Out of scope.`

**D10 Finding** (recorded: `findings/<A|D><n>.md`)
- Frontmatter: `v`, `plan`, `node`, `attempt`, `round` (`A1`), `agent` (`investigator`), `agent_id`,
  `source` (`gate` or `reviewer`), `finding_ids[]`, `fingerprints[]`.
- Body JSON (fenced in A1, unfenced in A2). `findings[]`: `id`, `rule_id`, `layer`, `files[]`,
  `root_cause`, `fingerprint`, `testable`, `suggested_test`, `untestable_reason`; envelope
  `previous_attempts[]`.
- Example fingerprint `GET-1|src/Uinsure.Policies.Api/Contracts/PolicyMappings.cs|canned-status-active-coincides`;
  example `untestable_reason`: `A source comment has no runtime behaviour, so no test can observe whether
  it is true; …`.

**D11 QA step** (written, results by the tester: `docs/qa/build-<node>.md`)
- Header: Rule IDs, Branch, Worktree, Commit under test, API URL.
- Sections: Preconditions, Execution record, Deviations, Starting the API, Hand requests H1–H6, Steps
  A–D, Exploratory notes, Sign-off.
- Step table: `#`, `Rule`, `Postman request`, `Steps / input`, `Expected`, `Actual`, `Pass/Fail`.
  Example: `1 | GET-1 | GET-1 · sold policy reads back in full → 200 | … | PASS`.
- The Rule column holds a bare rule ID or `SHAPE`; matrix links use `#<step number>`.

**D12 Sign-off** (QA `## Sign-off` table, plus the README Gates line)
- Rows: Tester, Date, Commit signed off, `dotnet test` result, Postman CLI result, Steps passed, Defects
  raised, Verdict, Signature. Examples: `Steps passed | 41 of 41`; `Verdict | ☐ Reject (findings above)
  ☑ Accept F2`; `Signature | David Morgan 19/10/2026 01:05`.
- Gates line: `red ✓ · pause 1 ✓ · green ✓ · integrate ✓ (full suite 374/374 at 223102a) · sign-off
  David 2026-10-19 223102a`. Loop event: `signoff(223102a7c40f2042674e3b677116c446244dfea7)`.

**D13 Context snapshot** (written: `docs/context/<yyyymmdd-hhmmss>-<slug>.md`)
- Frontmatter: `timestamp`, `previous-context`, `checkpoint`, `status`, `plan`, `node`, `phase`, `step`
  (nullable), `attempt`, `branch`, `worktree`, `head`, `tests`, `next-action`, `open-decisions`.
- Headings: Summary, Completed since last snapshot, Current state, Next action. Example: `head: ad7b6b0`,
  `tests: 374/374`, `phase: merge`.

**D14 PR** (loop events only, no PR files): `pr(17)` with detail `draft
https://github.com/dpmorgandev/uinsure-policies-api/pull/17`; `pr.comment(reviewer,6256697305)` with a

**Other files.** `reconciliation.md` (F0b only, written): lost receipts, renames, rulings. F0a:

## 4. Edge cases the UI must handle

- **F0a git-only:** a written README ("witnessed by git and trailers only"), no loop, activity, verdicts
  or matrix rows; receipts are hook logs and markdown (probes G1–G14, S1–S9).
- **TRAIL INCOMPLETE:** no README showed it at `ad7b6b0`. The instance found then was F1's loop event
  `trace.rendered(incomplete)` at attempt 2 (`BLOCKED. (1) QA rows use [SELL-n] in the Rule column; …`):
  a past state, not a final one. A fixture must supply the final-state case.
- **Empty rule tables:** F0b and F1b have a Rules header with no rows.
- **FAIL, then fix (F2):** attempt 1 `gate.stub` `ok:false` → `attempt++`; attempt 2 reviewer FAIL (R1 P1
  plus five P2) → attempt 3 and `investigation.opened(inv-001)`; attempt 3 `state(investigating)`,
  `findings(…A2.md)`, `state(in_progress)`; commits carry `Fixes-Finding: A1/I1`, `A2/I1`; re-review
  rounds `A3.2`. `ok:false` is a normal state for `gate.stub`, not an error.
- **Same-attempt re-review:** `A3` and `A3.2` share attempt 3.
- **Attempt 0:** F0b events show `attempt 0` while the DAG says 2.
- **Pinned tests:** `4 pass at HEAD: the 404 /problems/get-1 rows, already answered by the F1 bare GET
  (pinned, not red)`; `gate.red` with `exit:0`, `expect:"pinned (David: trait + gap-fill)"`.
- **Skipped task:** t5 `skipped`.
- **Missing verdict:** F0b `A1-reviewer.json` was overwritten and lost; `reconciled(A1-reviewer.json)` and
  `reconciliation.md` explain it.
- **Hook mismatch:** F1 `0e4fe2f | main | 1 | — | ✗`; F1 `762c994` had no activity record.
- **Rewritten SHAs:** F2 activity `d4ed4b35…` vs trailers `d2a46f5…` for the same subject. SHAs aren't
  stable across rebases.
- **Stale headers (verified):** F2's generated README still reads `status: done · PR #17 · merge pending`
  although `merged(…)` is in its loop (the README was rendered at 00:07:57Z, the merge event is
  00:10:40Z). Also: the DAG has F2 t17 and F0b t16 `pending` though merged; F0b `pr: null` in the DAG but
  "PR #6" in its README; F1b README `pause 1 ✗`. **The explorer must derive state from events, not trust
  headers,** and show disagreements rather than pick one.
- **Redactions:** `<outside-repo>` in `file`; `<user>` inside command text; `<root>` in F0a hook logs.
  Commands are truncated at about 200 characters.
- **Long strings:** finding `root_cause`, `what`, `why` about 1–3k characters; loop `detail` up to about
  600; QA "Actual" cells about 700.
- **Empty or null:** `findings:[]`, `rules_missing:[]`, blank refactor, `file:null`, `command:null`,
  `agent_id:null`, `tdd:null`, optional `detail`, `cmd`, `exit`.
- **Multiple `Fixes-Finding:` trailers** on one commit.
- **Escaped text:** `\|` in markdown cells.
- **Dates and zones:** signatures `19/10/2026` (DD/MM, UK time, BST), matrix ISO dates, `ts` in UTC.

## 5. Links

- **Rule → tests:** pass/total only; no test names or paths in the trail (tests are traited in source).
  Postman folders referenced by name only.
- **Rule → commits:** matrix `red`, `green`, `refactor` short SHAs; walkthrough rows give the rule per
  commit.
- **Rule → QA step:** `docs/qa/build-F2.md#1` (step numbers, not real markdown anchors).
- **Rule → PR:** `#17` in the matrix. Verdicts and findings link by SHA and `file:line` text.
- **Commit → node:** walkthrough and README. **Commit → finding:** `Fixes-Finding: A2/I1`.
- **Loop events → files:** `verdict(...)` and `findings(...)` embed repo-relative paths.
- **GitHub:** owner and repo `dpmorgandev/uinsure-policies-api`; PR URL
  `https://github.com/dpmorgandev/uinsure-policies-api/pull/17`; comment URLs `…#issuecomment-<id>`;
  commit URLs buildable from full SHAs. Merge SHAs: F2 `ad7b6b09…`, F1b `b2584f7a…`, F1 `c16703b4…`,
