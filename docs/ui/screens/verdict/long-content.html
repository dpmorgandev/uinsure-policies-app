R1 · P1 · rule GET-1

Where. src/Uinsure.Policies.Api/Contracts/PolicyMappings.cs:37

Why it matters. GET-1 returns the stored policy, and the F2 acceptance asks for the full response shape per api.md. Policy.HasClaims already exists end to end: PolicyRecord.HasClaims, PolicyRecordMapper.cs:21 into Policy.Restore, and PolicyRepository.cs:70. The comment says it is canned 'until F3 supplies the data', but that data is supplied today, so a canned stub value is left in green production code. The anti-oracle rule is broken too. PolicyResponseAssert.HasNoClaimsRefundsOrCancellation only ever expects false, and the Api.Tests PolicyBuilder passes a literal false to Restore with no override, so no test can tell the canned value from the stored one. A red test that seeds HasClaims=true and reads it back over HTTP must come before the mapping fix. Refunds, claims and cancellation have no domain data yet, so they are rightly canned.

Where. src/Uinsure.Policies.Api/Contracts/PolicyResponse.cs:3

Why it matters. This is on the code-quality slop list: a comment that is false at HEAD. The refactor step fixed the same kind of stale comment on TwoDecimalPlacesConverter (7023420, 803c898) but missed this one. PolicyMappings.cs:23 already lists what is still canned.

Routed to. builder

R3 · P2 · rule GET-1

Where. src/Uinsure.Policies.Api/Contracts/TwoDecimalPlacesConverter.cs:17

Why it matters. CLAUDE.md says to round money only through Money.Round. At HEAD the invariant holds: the H6 400 rejects more than 2 dp by value before any 422 echo, and stored amounts come only from accepted sales. But F3's refunds will go through this converter, and "F2" formatting would hide a missing or wrong Money.Round (CANCEL-6) in every Api test. The change to problem echoes (-1e27 now written -1000000000000000000000000000.00) is consistent with the api.md money convention, but only gate.run evidences it. No Api test pins the echo's text, and the Postman decimal.MinValue test's include('"amount":-79228162514264337593543950335') is a prefix match that passes with or without '.00'.

Routed to. builder

R4 · P2 · rule GET-1

Where. src/Uinsure.Policies.Api/Filters/RejectUnknownQueryParametersFilter.cs:11

Why it matters. The architecture skill says 'an unbound query key (case-insensitive) gives errors[key]', and requirements say an unknown query parameter returns 400. Route-bound, body-bound and special parameters are counted as known query keys. The only test is ?colour=red.

Routed to. builder

R5 · P2 · rule GET-1

Where. tests/Uinsure.Policies.Api.Tests/RetrieveCurrentTermTests.cs:76

Why it matters. The tdd-outside-in skill requires a full read-back of every field the node's response carries, and status is a GET-1 field. The row is stub-proof now only through currentTermNumber (canned 0 vs 1). A status literal would pin it on a second derived value, as the other rows in this class do.

Routed to. tester

R6 · P2 · rule GET-1

Where. tests/Uinsure.Policies.Services.Tests/PolicyServiceGetDetailsTests.cs:29

Why it matters. The tdd-outside-in skill wants Services.Tests where Services has logic, and PolicyService.cs:57-63 builds the GET-1 violation. RuleCoverageTests passes because unit traits exist, so this does not block coverage. But GET-1's failure row has no unit-level test. The orchestrator recorded this gap in gate.green at 311ccb6.
