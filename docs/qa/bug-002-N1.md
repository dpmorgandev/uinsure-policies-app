## What changed at attempt 3

- The page waits for the compile. While the dev server compiles the trail, `/trace.json` answers 503 with the
  header `X-Docket-Trace: compiling`, and the loader asks again every 500 ms until it gets the trail. A 503 marked
  `failed`, or a 503 with no marker, is final. Steps 7 and 10.
- The esproj's `StartupCommand` is `node scripts/dev.mjs --port 4170 --strictPort`, so it names `npm ci` on a clone
  with no packages instead of running `npx vite`. Step 2.
- The `/trace` middleware decodes only `/trace.json` and `/trace/…` paths. A malformed escape there answers 400, a
  directory answers 404, and nothing answers 500. Step 9.

## Commands the steps use

P1, the poller. Run it in Shell 2 from any directory. It asks for `/trace.json` every 100 ms and prints the status,
the `X-Docket-Trace` header in brackets, and the first 60 characters of the body. `000` means the port refused the
connection. It stops at the first 200, or after a minute.

```powershell
$f = "$env:TEMP\n1-trace.txt"; $h = "$env:TEMP\n1-head.txt"; Remove-Item $f, $h -ErrorAction SilentlyContinue
for ($i = 0; $i -lt 600; $i++) {
  $c = curl.exe -s -D $h -o $f -w "%{http_code}" http://localhost:4170/trace.json
  $m = (Select-String -Path $h -Pattern '^X-Docket-Trace:\s*(\S+)' -ErrorAction SilentlyContinue).Matches.Groups[1].Value
  $b = [string](Get-Content $f -Raw -ErrorAction SilentlyContinue)
  "$c [$m] $($b.Substring(0, [Math]::Min(60, $b.Length)))"
  if ($c -eq '200') { break }
  Start-Sleep -Milliseconds 100
}
```

P2 reads a compiled trail's stamp. Run it in Shell 1 from clone web, with `<file>` set to `public\trace.json` or
`dist\trace.json`.

```powershell
(Get-Content <file> -Raw | ConvertFrom-Json).compiledAt | Format-List sha, utc
```

P3 asks the dev server for one path, sent as written, and prints the status and the body. Run it in Shell 1 from any
directory, with `<path>` set as the step says.

```powershell
curl.exe -s --path-as-is -w "`n%{http_code}`n" "http://localhost:4170<path>"
```

## Notes

1. **Visual Studio might restore the packages before F5 gets the chance to fail.** The JavaScript project system can
   run its own npm restore when it opens an `.esproj`. When it does, step 3 can't show the stop message, and step 2
   is the proof. Either outcome meets the acceptance: the packages are restored, or the launch stops and names
   `npm ci`. What fails is a `Cannot find module …vite.js`, or `npx` going to the registry for Vite.
2. **The 503 window can be short.** Step 5's 300 commits lengthen the compile, as the unit test does, but on a fast
   machine it might still end in well under a second. The poller and the page only see the 503 if one of their asks
   lands inside that window. If P1 jumps from `000` to `200`, or the page never shows **Loading**, stop the dev
   server, delete `public\trace.json` and `public\trace`, add more commits with step 5's loop (`1..1000`), and run
   steps 6 and 7 again. A straight `000`→`200` still shows nothing broken, because the port never served a 404 or an
   older file.
3. **The esproj gap from attempt 1 is fixed.** The esproj's `StartupCommand` read `npx vite --port 4170 --strictPort`,
   which on a clone with no packages went to the registry for Vite. At 4a121f63 it runs `scripts/dev.mjs`, the same
   guarded script as the `Vite dev server` configuration in `.vscode/launch.json`. Step 2 runs it as written. If any
   F5 path still runs `npx vite`, write it as a defect against step 2 or 3.
4. **I haven't run these steps.** Visual Studio, the clone and the browser are outside what I run at the QA step. The
   expected text comes from `scripts/dev.mjs`, `vite.config.ts`, `app/data/trace.ts`, `app/shell/DataNotice.tsx`,
   `Docket.Web.esproj`, `.vscode/launch.json`, `Uinsure.Policies.slnLaunch`, `package.json` and `.nvmrc` at 4d85e145.
   Step 7 assumes Vite's `--open` opens the tab when the port starts listening, before the compile ends. If the tab
   only opens after the trail is drawn, open it yourself at the first 503, as the step says.
5. Delete `$env:TEMP\n1-fresh`, `$env:TEMP\n1-trace.txt` and `$env:TEMP\n1-head.txt` when you're done.
