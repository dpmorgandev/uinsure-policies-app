## What changed in N4

- **The matrix's Step 3 is built.** On main, "Test counts are per node" held the kit's not-built-yet box. It now
  reads "The matrix counts a rule's tests at the node that built it, while the rule page lists every test traited
  with it, so the two figures can differ. For example SELL-1 has 22 of 22 at F1." The example is the first rule in
  the table that has a node and a count, taken from trace.json. It is not written into the screen.
- **The activity screen's "not drawn as lanes" notice is the kit's.** On main it was the screen's own
  `<p class="s-events-note">`. Now `AgentLanes` takes the undrawn lines and draws the notice inside its own region,
  with an info icon (`kit-agent-lanes__notice`). **The real trail has no undrawn line.** Every activity line names an
  agent the kit draws, so on HEAD's trail the notice never shows. Step 6 makes two lines undrawn with a console
  patch, inside the page, to show it.
- **The Plan entry is main's again (steer D1).** Green first added a plan index page. You ruled at Pause 1 that the
  plan page with its tabs is what you want, and main already drew that. Round D1 removed the index, and `Frame.tsx` is
  main's again (the D1 gate shows a nil diff against origin/main). What N4 adds for DAG-1 is the tests: each tab is
  clicked in turn, only inside the **Plans** landmark, and `aria-current` must move with it.
- **One status-to-tone mapping.** `app/workbench/statusTone.ts` maps `Pending` to pending (grey, clock), `Active`
  to pass (green, tick), `Expired` to warn (amber, triangle) and `Cancelled` to fail (red, cross). Any other word is
  warn. Sell, Cancel, Claim, Renew and the policy view all use it. On main, Sell drew every status as a green tick,
  Cancel did the same unless the re-read failed, and Claim and Renew drew anything but `Active` amber.
- **The drawer says "Failed" when nothing answered.** A request with no response is now tagged `Failed` (red, cross,
  with "(no response)" for screen readers). The live region reads "Request #*n* failed: no response". On main, after
  N3, it read `Problem` and "Request #*n* answered". A request that did get an answer, such as the proxy's 502, is
  drawn as before.
- **The cancel screen is keyed on the policy.** A hash change from one policy's cancel route to another's used to
  keep the first policy's quote, cancel answer and stale mark, because the route kept the same element. It now starts
  afresh.

## Notes

1. **The console patch for steps 6 to 8.** Paste it as one block. It answers N5's activity chunk with line 1's agent
   renamed to `design-auditor`, which isn't one of the kit's agents, and line 2's agent removed:

   ```js
   const realFetchA = window.fetch;
   window.fetch = async (input, init) => {
     const response = await realFetchA(input, init);
     if (!String(input).endsWith('trace/bug-002/N5/activity.json')) return response;
     const lines = await response.json();
     lines[0].agent = 'design-auditor';
     lines[1].agent = null;
     return new Response(JSON.stringify(lines), { status: 200, headers: { 'content-type': 'application/json' } });
   };
   ```

   It works because the activity screen fetches its chunk through the global `fetch` each time it opens a node
   (`app/data/trace.ts`, `loadActivity`), and the chunk is a JSON array of the log's lines. The page already holds
   trace.json, so nothing else is fetched again. It changes only what this tab sees: the trail and the files on disk
   are untouched. Step 8 puts the real fetch back.
2. **The console patch for step 20.** It's N3's, with its own name, so it doesn't clash with note 1's:

   ```js
   const realFetchS = window.fetch;
   window.fetch = (input, init) =>
     String(input) === '/api/policies/QA-N4-STALE' && (init?.method ?? 'GET') === 'GET'
       ? Promise.resolve(new Response('{"status":503,"title":"Service Unavailable"}', { status: 503, headers: { 'content-type': 'application/problem+json' } }))
   ```
