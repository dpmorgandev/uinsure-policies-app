The gap (bug-002/N4, HONEST-1): InspectorDrawer can't tell a request the API answered with a problem from a request that got no response at all (the fetch was rejected: the API down or blocked). For any outcome but pending it announces "Request #n answered", and a problem with no HTTP status is tagged "Problem (problem)". A request with outcome 'problem' and no status was never answered, so the drawer should announce it as failed (for example "Request #1 failed: no response") and tag it "Failed", never "answered" or "Problem". A problem with a status keeps today's announcement and tag. Draw the no-response request within the existing `problem` example. Add no new catalog state.
