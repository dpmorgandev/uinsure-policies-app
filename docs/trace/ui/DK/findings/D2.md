# D2: alignment defects in the kit, carried into the screens stage

David at G3: "I noticed some alignment issues especially with errors and error icons", "I think there are
lots in place please review the review.html visually", and "a huge chunk of the review file is empty". On
the budget: "Fix it in the screens stage". No kit batch is regenerated; these go to G4.

The main session reviewed per-component screenshots at 1440 and measured overflow at 1440 and 390, at
David's request. Owning batch in brackets.

## Errors and error icons

1. Invalid inputs grow wider than their valid state: text-input, date-input, text-area, select and
   money-input each add an icon slot outside the box, so the field jumps width (primitives-b).
2. The in-field error icon is placed at a fixed offset, not at the right edge: on money-input it sits on
   top of the right-aligned digits; on select it is jammed against the chevron (primitives-b).
3. Two icons per error: the message carries one and the input carries another (primitives-b, field).
4. Two error message styles: the primitives' message is small with a smaller icon and wraps early
   ("2026-10-" / "19."), while inline-error is larger and bold (primitives-b, patterns-b).
5. inline-error "several on one field" shows the icon and a bullet together on the first item, so the
   items don't align (patterns-b).
6. field "invalid" pushes the label, hint and input right of the plain fields by the width of its error
   bar, and the invalid input is wider than the plain one (patterns-b).
7. form-section and repeatable-group with errors: the inputs run past the right edge of the grey card
   (measured 674 against 672) (patterns-b).
8. radio-group invalid: the icon in the legend and the error bar indent the options away from the valid
   state (primitives-b).

    quote-cancel-compare, dag-graph, dag-table, the inputs and text-area) (layout, project, patterns).
