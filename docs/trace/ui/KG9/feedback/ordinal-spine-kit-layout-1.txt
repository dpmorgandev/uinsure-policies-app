DagGraph draws its text equivalent with DagTable, but renders it as <DagTable nodes={nodes} /> and gives the caller no way to set the rule chips' links. DagTable already takes a ruleHref, so every rule chip in DagGraph's text equivalent falls back to RuleChip's default /rules/<id>. That isn't a route in Docket's hash-routed app, where a rule's page is #/rules/<id>. So on the plan page and on the overview's build plan at a glance, which draw DagGraph, a rule chip opens nothing. DagGraph must take an optional ruleHref with DagTable's signature and pass it through to DagTable, keeping today's default when the caller sets none, with a kit test that a caller-set link reaches the chips in DagGraph's text equivalent. Also, the DagNode type that DagGraph's nodes prop takes isn't exported from the kit's public entry, so a screen has to spell it DagGraphProps['nodes'][number]: export DagNode from dag-table's index so that the barrel carries it. No new catalog state is needed.
