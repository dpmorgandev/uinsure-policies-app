# inv-006: W1 review fails on scope, a kit gap and an untested section, not the built screens
## Question
Why does the reviewer FAIL ui/W1 at attempt 2, and is each P1 cause in the screens, the tests, or the node's scope?
## Hypothesis
None of the three P1s is a screen defect the existing tests could have caught; each sits where nothing could fail.
R1 is scope: the derived reference gives W1 regions of the cancel, renew and claim screens, but t6 names only home,
sell and policy and no W1 spec visits those routes, so t2's canned content survived green. R2 is a kit gap the
builder patched in the shell instead of reporting. R3 is a test gap: no W1 test seeds a refund, claim or
cancellation. Disproved by: derived.json not giving W1 those regions; a W1 test visiting cancel, renew or claim;
the kit already letting a caller set a rule chip's link; or a W1 test seeding a refund, claim or cancellation.
