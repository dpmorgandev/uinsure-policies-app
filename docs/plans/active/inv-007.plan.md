# inv-007: U3 review fails on values the kit can't draw and a fixed provenance sentence
## Question
Why does U3's screen layer render a recorded P0 verdict finding as P2 at attempt 2, and is the cause in the kit's VerdictCard severity type or in the screen?
## Hypothesis
The kit's VerdictCard types severity as 'P1' | 'P2', so the screens coerce P0 to P2. The reviewer's other three
findings (a fixed "recorded by the orchestrator" sentence, an ok-less gate drawn as waived, a null testable drawn as
Untestable) are screen mappings that turn a missing or differing value into a claim, and no fixture holds any of
these values. Disproved by VerdictCard accepting P0, or by a fixture already holding one of these cases.
## Evidence

- docs/trace/ui/U3/findings/A2.md: the investigator's diagnosis, I1-I5
- src/web/kit/project/verdict-card/VerdictCard.tsx:14, :164: severity 'P1' | 'P2', tone knows only P1;
  src/web/app/explorer/verdict/Verdict.tsx:116 and Ladder.tsx:85 write `severity === 'P1' ? 'P1' : 'P2'`
- docs/ui/components.md:89, :91, :92: the gate-row, verdict-card and finding-card rows list no P0, no
  "ok not recorded" and no "testable not recorded" state
- src/web/app/explorer/loop/Loop.tsx:42-43: the provenance sentence is a constant; 37 real loop lines carry
  source 'reconciled'; the signed-off node reference words it "per its source field"
- tests/web/fixtures/trails/**: every severity P1 or P2, every loop line source orchestrator, every gate line has ok,
  every finding has a boolean testable
## Findings
**Yes: the cause of R1 is in the kit** (VerdictCard can't say P0), with a screen coercion on top. Of the other
three, R2 is in the screen alone; R3 and R4 are kit gaps too, which disproves that part of the hypothesis.
Diagnosis in [findings/A2.md](../../trace/ui/U3/findings/A2.md).
