# inv-005: U0b review fails on the compiler's missing attempt and unscanned git values
## Question
Why does the reviewer FAIL ui/U0b at attempt 4 on HONEST-1 and DATA-5, and is the cause in the compiler code, in the tests, or in both?
## Hypothesis
The compiler's activity chunk and commit output were written to the field lists the t5 unit tests named, so code and tests share the same omissions (attempt; trailer values and compiledAt.ref), and the Playwright activity read-back skips Attempt for the same reason. Disproved if any test at HEAD asserts attempt in the activity chunk or on the page, or plants a denylisted trailer value, and still passes against the current compiler.
## Evidence
- docs/trace/ui/U0b/verdicts/A4-reviewer.json: FAIL, P1 R1-R3 (HONEST-1, DATA-5), P2 R4-R5 (DATA-1)
- docs/trace/ui/U0b/verdicts/A4-security.json: PASS; P2 S2 is R3's cause, S1 and S3 are hygiene
- docs/trace/ui/U0b/findings/A4.md: the investigator's diagnosis, I1-I6
- docs/trace/ui/U0b/packet/: the reviewed diff, trailers and gates at 690ad15
- docs/trace/ui/U0b/loop.jsonl:78-82: the verdicts, attempt 4 → 5 and this investigation
## Findings
Both. The cause sits in the compiler and in the tests together, and no test at HEAD names attempt or plants a value from git outside the commit subject, so the hypothesis holds. One part does not: the compiler's field list is not copied from the tests (it emits line, ts and commit, which they don't name), but both leave out the same fields. See [findings/A4.md](../../trace/ui/U0b/findings/A4.md).
- I1 (new, HONEST-1, blocking): the activity chunk is built from a fixed field list without attempt (src/web/compiler/index.ts:149), so every Attempt cell shows a dash the trail contradicts.
- I2 (new, HONEST-1, blocking): the tests' ActivityLine has no attempt (tests/web/unit/compiler/support/trail.ts:51-56, tests/web/e2e/U0b/support/trail.ts:145-150), so the chunk test (data-1.test.ts:103) and the read-back (a11y-1.spec.ts:171-179) never see I1. inv-004's A2/I2 test listed the same columns.
- I3 (new, DATA-5, blocking): the denylist scans the compiler's inputs and the commit subject only (index.ts:88-93, :111); trailer values (:112-124) and compiledAt.ref (:206) are written unscanned. It is security's S2 too.
- I4 (new, DATA-5, blocking): the only test with a value from git plants it in the subject (data-5.test.ts:93-108), while its header claims every emitted value.
- I5 (new, DATA-1, non-blocking): trailersOf keeps only the last value of a repeated key (src/web/compiler/git.ts:40), so commits with several Fixes-Finding lines lose all but one; no U0b screen reads it, U3 is the first reader.
- I6 (new, DATA-1, non-blocking): events, verdicts and rules[].status/red/green are filled by parsers no red test drives (index.ts:154-200); no U0b screen reads them.
