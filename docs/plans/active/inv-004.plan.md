# inv-004: U0b t9 A11Y-1 fails on kit and test causes, not the screens
## Question
Why does t9's gate.green fail A11Y-1 on U0b at attempt 2 (e2e 59/62), and is each failure's cause in the screen layer, the kit or the tests?
## Hypothesis
None of the three is a screen-layer defect. The two axe failures are colour contrast on the kit's fail StatusTag
(the tone on its own 10% tint, about 4.4:1, under 4.5:1), which the screens must show. The activity "Line"
failure is the test reading innerText while the kit's DataTable uppercases its headers. Disproved if an axe
violation names an app-owned node or another axe rule, or if the Line assertion fails for a reason other than case.
## Evidence
- docs/trace/ui/U0b/loop.jsonl: gate.green (t9) FAIL at 8049a28, e2e 59/62, three A11Y-1 tests; its detail names light 1440 only, while the test artifacts show light 390 failing too
- src/web/test-results/*/error-context.md: axe color-contrast (serious) on one kit node per page, .kit-status-tag__fail > span on #/about and .kit-status-tag__tag > span on the unread overview; dark is clean
- src/web/kit/primitives/status-tag/StatusTag.module.css:13-14, :24-25 and tokens.css:31: the fail tone #ca3535 on its 10% tint over #ffffff measures about 4.45:1
- docs/ui/styles.md:69-71: G4 measured the fail tone on background and surface only, never on the tag's own fill
- tests/web/e2e/U0b/a11y-1.spec.ts:144-147 and DataTable.module.css:45: the header lookup reads innerText after `text-transform: uppercase`
- src/web/app/shell/Frame.tsx:55-66, :95-101, frame.css: a screen-built frame for the unread trace, with no skip link and no footer
- docs/ui/screens/overview/error.html:24, :87 against tests/web/e2e/U0b/support/app.ts:108-112: the signed-off error state shows a snapshot stamp that the HONEST-1 tests forbid
- src/web/vite.config.ts:33-34 and support/app.ts:118-123: CSS minification turned off at stub, to fit a string comparison of the background token
## Findings
Yes, the hypothesis holds: none of the three failures is in the screen layer. Two are in the kit, one is in a
test, and investigating them turned up two more defects behind them. Findings: [findings/A2.md](../../trace/ui/U0b/findings/A2.md).
- I1 (new, kit): the fail StatusTag's text on its own tint is 4.45:1 in the light theme (StatusTag.module.css:13-14, :24-25). It fails both axe tests. It dates from G4: no kit test runs axe, and KG1's re-audit compared screenshots only.
- I2 (new, test): a11y-1.spec.ts:144-147 reads headers as rendered text after the kit's uppercase. Only "Line" failed because it is looked up first. The row assertions after it have not yet run against the built screen.
- I3 (new, kit plus a ruling): with no kit frame that can state "no snapshot", the builder built its own frame (Frame.tsx:55-66, frame.css). It dropped the skip link, the footer landmark and the 390 layout, and it should have stopped and reported instead. The signed-off error.html shows a stamp that HONEST-1 forbids, so the reference and the tests contradict each other.
- I4 (new, test): the theme check compares the token's spelling (support/app.ts:118-123). The builder turned CSS minification off at stub to fit it (vite.config.ts:33-34).
- None repeats a fingerprint from A1 or D1.

## Why
The attempt-3 stop on ui/U0b: gate.green FAIL on t9 (the screen layer), after attempt 1's gate.red FAIL (A1).
## Approach
This investigation was read-only: the U0b trail (loop.jsonl, findings A1 and D1), the failing tests' artifacts,
the kit, the screens and the signed-off references, with one investigator dispatch. The time box was 30m from
23:43Z, and it held.
## Rejected alternatives
- Override the fail tone, or the header casing, in screen CSS: react-web forbids patching the kit in a screen, and the fix would hold for U0b alone while every later screen showing a fail tag inherits the defect.
- Let the reference's footer win for the unread state: the error page would show a snapshot time the unread trail cannot hold, which breaks HONEST-1. Re-signing the reference costs less than shipping an untrue stamp.
- Keep the builder's UnreadFrame and add a skip link to it: the screen would still own a copy of the kit's layout, which react-web forbids, and it would drift from AppShell.
