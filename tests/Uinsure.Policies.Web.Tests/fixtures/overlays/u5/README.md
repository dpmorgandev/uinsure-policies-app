# u5 (an overlay on the `complete` trail)

Not a trail of its own: files laid over a replayed `complete` trail (`../../trails/complete/README.md`)
before it is committed, so U5's tests read the clean build/F1 run plus what U5's screens need. The
tests copy `tree/` into the replayed repo with `cpSync` and the compiler reads it at HEAD.

- **`docs/context/`: four snapshots across two days** (CTX-1).
  - `20261018-090000-f1-started.md`: build/F1, `in-progress`, next action "Run the F1 red step".
  - `20261018-171500-f1-pause-one.md`: build/F1, `blocked`, next action "David opens the stub routes at pause 1".
  - `20261019-081000-day-two-resumed.md`: no plan, no node (both `null`), `in-progress`, next action
    "Resume F1 from pause 1 after David's ruling".
  - `20261019-120000-no-front-matter.md`: a snapshot with no front matter. It is not a session the
    compiler can date: it is reported in `problems[]` with its file, and never guessed into the timeline.

  So the timeline is three sessions, oldest first, two on 2026-10-18 and one on 2026-10-19.
- **`docs/trace/harness.json`: the generated harness file** (AGENT-3, DATA-7), in render-trace's shape:
  two agents (`tester`, `builder`), two skills, two hooks (`guard-agent.mjs` guarding G1 and
  `gate-red.mjs` guarding G4 and G5), provenance "generated by .claude/scripts/render-trace.mjs from
  .claude/ at tree a1b2c3d", and the denylist's source blob.

**Expected:** the compile succeeds; `sessions[]` holds the three dated snapshots in time order, each
with `file`, `ts`, `slug`, `plan`, `node`, `status` and `nextAction` from its front matter; `problems[]`
names the undated one; `harness` is the file's content, field for field. build/F1's A1 verdicts carry
their envelope's `ts` (2026-10-18T16:00:00Z) and `attempt` (1) (STATS-1).
